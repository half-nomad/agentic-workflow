# Duet Mode

$ARGUMENTS

---

**연주자는 클로드와 코덱스. 설계 관문에는 architect 가 함께 앉는다.**

이 모드는 한 문장으로 정의된다: **네이티브 plan mode 에 코덱스 관문 두 개를 붙이고, 설계 관문에 `@architect` 를 병렬로 둔 것.**
그 사이는 전부 클로드 자율이다. 훅 없음, 상태 파일 없음, 절차표 없음.

> **마에스트로와의 관계 (v0.4.0)**: 되돌리기 어려운 작업도 이 모드가 받는다(§되돌리기 어려운 작업).
> `/maestro` 는 **사용자가 이름으로 부를 때만** 쓰고, 클로드는 제안하지 않는다. 근거: 실사용 프로젝트에서
> 마에스트로 세션의 출력 토큰 중앙값이 duet 의 약 2.2배였고(작업 난이도는 통제 안 된 비교), 오케스트레이터가
> 전달자가 되면서 중간 전달 손실이 4회 기록됐다. 값을 한 것 — 다른 눈 — 은 이 모드에 그대로 있다.

## 발동 — 자동으로 켜지지 않는다

**이 모드는 사용자가 `/duet` 을 치거나 말로 요청할 때만 실행된다.** 아래 기준에 맞아 보여도 **스스로 켜지 않는다.**

맞아 보이면 **한 줄로 제안하고 사용자가 정한다:**

> *"이건 설계 갈래가 둘이라 `/duet` 이 맞아 보입니다 — 켤까요?"*

**왜 제안까지만 하나**: 스스로 켜면 **무엇을 안 켰어야 했는지가 기록에 안 남는다.** 수락·거절 기록이 곧 나중에 자동 발동으로 넘어갈 근거가 된다.
워크플로 밖에서 클로드가 스스로 architect·코덱스를 부른 기록은 0건이었다(2026-08-23~09-28 세션 24개, 코덱스 호출 4건은 전부 사용자 지시·개발·런 내부) — "필요할 때 알아서 부른다" 는 실제로 일어나지 않았다.

**안 켜기로 판단했을 때도 한 줄 남긴다** — *"이건 답이 하나로 정해져 있어 그냥 하겠습니다"* 정도면 된다.
켠 것만 기록에 남으면 **안 켜서 놓친 경우가 통째로 안 보인다.**

**제안 기록**: 제안할 때마다(안 켜기로 한 경계선 판단 포함) `.agentic/duet-runs.md` 의 `## 제안 기록` 절에 한 줄 — `날짜 · 작업 · 제안한 층 · 사용자 답`.
**푸는 조건**: 제안 기록이 10건 쌓이면 수락·거절을 사용자와 함께 보고 자동 발동 여부를 정한다. 10건은 논의 시점이지 안전성 증명 기준이 아니다.

## 라우팅 — 이 모드가 맞는 작업인가

**파일 수로 나누지 않는다.** 20개 파일의 기계적 rename 은 저위험이고, 한 파일의 인증·권한 변경은
고위험이다. 세는 것으로는 위험이 안 잡힌다 — v5.0 이 *"파일 3개면 무조건 complex"* 판정표를
오분류 유도라는 이유로 이미 삭제했는데, 그 실수를 다시 하지 않는다.

**`/duet` 기준 — 하나라도 해당하면:**

- **불확실한 설계 판단이 있다** — 갈래가 둘 이상이고 어느 쪽이 맞는지 코드만 봐서는 안 갈린다
- **모듈 경계 · 상태 · 공개 계약에 영향** — 남이 의존하는 모양이 바뀐다
- **독립 검토가 실제로 유용하다** — 내가 놓칠 만한 각도가 있다
- **되돌릴 수 있으나 실패 시 재작업 비용이 크다**
- **되돌리기 어렵다** — 보안 · 결제 · 운영 데이터 · 마이그레이션 · 데이터 삭제/이동 · 배포 · 공개 API · 외부 발송 → §되돌리기 어려운 작업 규칙을 켠다

**그 외 — 기본 모드.** 답이 하나로 정해져 있고 실패해도 되돌리면 그만인 작업.

**`/maestro`** — 사용자가 이름으로 부를 때만. 클로드는 제안하지 않는다.

**작업 중 되돌리기 어려운 성격이 드러나면 그 자리에서 §되돌리기 어려운 작업 규칙을 켜고** 사용자에게 한 줄로 알린다 — 판단을 숨기지 않는다.

## 관문 하나 — 설계 (코덱스 1회 + `@architect` 병렬)

계획 초안을 쓴 뒤, **승인 요청 전에** 코덱스와 `@architect` 에 **동시에** 넘긴다. 순서가 중요하다: 검토를 반영한
계획으로 승인을 받아야 승인이 통제가 된다.

**코덱스 호출 명령은 `~/.claude/skills/maestro/reference/codex-cli.md` 가 유일한 정본이다** — 여기 복제하지 않는다
(v0.3.1 이 companion 경로를 본문에 고정해 두었다가 플러그인이 빠지자 제출이 빈 경로로 멈췄다). 구속 규칙 둘만 여기 둔다:
**프롬프트는 stdin 으로만** · **서브에이전트를 거치지 않고 CLI 를 직접 부른다.**

코덱스 프롬프트 골격 — **네 절 전부 넣는다**:

1. **배경** — 무엇이 기존 구조이고 무엇이 이번 변경인가. 링크로 대신하지 않는다.
   코덱스는 프로젝트 컨텍스트가 0이라, 이 절을 빼면 **원래 그랬던 것을 이번 결함으로 읽는다.**
2. **계획 전문** — 요약이 아니라 그대로.
3. **요구 하나 — 반증**: 이 계획의 사실 주장 중 코드와 어긋나는 것. 파일·줄 번호로.
4. **요구 둘 — 대안**: *"이 계획이 틀렸다면 무엇을 대신 하겠나."* 반박만 받으면 검토이고,
   대안까지 받아야 **설계 참여**다. 이 한 줄이 이 관문의 존재 이유다.

**`@architect`** (Agent 도구, `subagent_type: "architect"` — 모델은 정의 파일에 고정): 같은 배경과 계획 전문을 주고
설계 검토를 받는다 — 데이터 주인 · 불변 조건 · 실패 처리 · 계획이 안 본 경로. 의뢰서에 **"코덱스를 따로 부르지 않는다"** 를
적는다 — architect 정의는 고위험 판단에서 코덱스를 스스로 부를 수 있게 돼 있어, 적지 않으면 같은 관문에서 코덱스가 두 번 돈다.
근거: v0.3.x 에서 architect 를 빼고 그림자(완성 후 개입 없는 검토)로만 붙였더니 7런 중 6런에서 발견이 있었고,
그중 2건은 무게가 있었다 — 2026-08-24 *예약 4명이 1명으로 조용히 확정* (코덱스 두 관문 통과 뒤), 2026-09-04 파기 집합 누락.

**받은 뒤**: 지적을 코드로 확인한다. 사실인 것만 반영하고, 기각한 것은 기각 사유를 계획에
한 줄 남긴다. **클로드가 채택 여부를 판단한다 — 코덱스도 architect 도 계획을 정하지 않는다.**
리뷰어의 주장을 열어 보지 않고 계획·지침에 옮기지 않는다 — 마에스트로 런에서 두 번 틀렸다.

**관문1 코덱스를 끄는 경우는 둘뿐**: 사용자 modifier(`"코덱스 없이"`) · 확립된 패턴의 단순 확장(레포 안에
원본이 있는 복제 수준 — **되돌리기 어려운 작업에는 적용하지 않는다**). 껐으면 **관문 둘을 필수로 만든다.** architect 는 남는다.

## 네이티브 구간 — 전부 자율

**클로드가 직접 짠다.** 위임 금지 훅이 없고, 서브에이전트 호출 의무도 없다.
컨텍스트가 감당 안 될 만큼 큰 작업이면 **스스로 판단해서** 위임한다 — 허용이지 강제가 아니다.

### 추가 서브에이전트 — 작업마다 판단하고, 판단을 남긴다 (v0.4.1)

`@architect` 외에 서브에이전트를 더 쓸지는 **강제도 금지도 아니다.** 필요한 작업이 있고 해 보니 필요 없던 작업이 있을 것이라, 규칙으로 못 박지 않고 **작업마다 판단하되 그 판단을 기록해 근거로 쌓는다.**

1. **착수 때 한 줄** — 계획을 낼 때 *"이번엔 architect 외에 ○○ 를 추가한다"* 또는 *"추가 없이 간다"* 와 이유를 적는다. 애매하면 사용자에게 묻고, 명백하면 한 줄만 남긴다.
2. **검토할 신호** (해당하면 켜는 *후보*이지 의무가 아니다):
   - 같은 변형을 여러 파일에 기계적으로 해야 한다 → 병렬 위임
   - 돈·권한·개인정보 로직이라 **테스트를 구현자와 다른 눈**이 써야 한다 → 테스트 작성 위임 (구현은 건드리지 않게 한다)
   - 소비처 전수 조사처럼 읽기만 넓게 한다 → `Explore`
   - 화면 변화가 커서 확인을 따로 맡길 만하다
3. **끝에 한 줄 평가** — 그 에이전트가 **결정을 바꿨는지**, 비용만 들었는지 적는다 (§기록의 `추가 서브에이전트` 칸).

지켜야 할 것은 하나다 — 검증자(코덱스·architect·리뷰어)는 고치지 않는다는 `고치는 것은 클로드` 규칙은 추가 에이전트에도 그대로다. 위임받은 에이전트는 맡은 범위만 하고 검증자 역할을 겸하지 않는다. 서브에이전트 모델은 사용자·프로젝트가 정한 기본값을 따른다.

테스트·린트·빌드는 클로드가 직접 돌린다. **프로젝트에 검증 명령 등록 파일(예: `.claude/maestro-axes.md`)이 있으면 그것을 먼저 따른다** —
등록이 추정보다 우선이다. 없으면 프로젝트에서 찾는다 (`package.json` scripts · `Makefile` · CI 설정 · README · `CLAUDE.md`).

**계획서의 사실 주장은 확인한 것만 적는다** — 파일 수 · 건수 · 컬럼·메서드 이름 · 영향 범위는
코드로 확인하고 쓴다. 확인 안 했으면 `추정` 이라고 표시한다. 확인 방법이 곧 검증 기대치가
되므로, 틀린 사실은 멀쩡한 코드를 결함으로 오판할 기대치를 심는다.

## 관문 둘 — 구현 검토 (코덱스 1회)

**두 가지 다른 일이다. 섞지 않는다.**

| 축 | 무엇 | 안전성 |
|---|---|---|
| **A-read — 구현 검토** | 결함·회귀 경로를 찾는 **읽기 검토**. 파일을 안 건드린다 | 항상 안전 — **기본값** |
| **A-mut — 변형 검사(mutation)** | 구현을 일부러 틀리게 바꿔 **테스트가 실제로 죽는지** 확인 | **격리 가능할 때만** |

**A-mut 이 필요한 이유**: 통과하지만 아무것도 지키지 않는 단언은 읽어서는 안 보인다
(실측: 큐 경계 계약에서 61개 테스트가 전부 통과했는데 아무것도 안 지키고 있었다).
**죽지 않는 자리가 이 축의 산출이다.**

**A-mut 은 사용자 작업 트리를 훼손하지 않는다.** 격리 수단을 이 순서로 고른다:

1. **격리 worktree** — `git worktree add` 로 별도 트리에서 변형하고 통째로 폐기한다. **1순위.**
   코덱스에게는 이 worktree 에만 쓰기 권한을 준다 (`codex-cli.md` — 사용자 작업 트리에 쓰기 권한을 주지 않는다).
2. **원 트리 + 파일 백업** — **worktree 가 실제로 막혔을 때만.** 훅이 자격증명 파일 복사를
   거부하는 환경이 실재한다(2026-08-17 런). 이 경로에서는 **코덱스가 변형 목록만 읽기 전용으로 내고,
   적용·되돌림은 클로드가 한다.** 전제 셋을 먼저 만족해야 한다:
   - worktree 가 **왜** 막혔는지 한 줄로 확인했다 (추측으로 이 경로에 오지 않는다)
   - 변형할 **파일마다 원문을 백업**했다(`cp -p`) — 변형은 그 파일들에만 넣고, `git add` 는 하지 않는다
     (인덱스를 건드리지 않으면 스테이징 상태는 그대로다). diff·체크섬 스냅샷은 원문을 되살릴 수 없어서 쓰지 않는다
   - 변형마다 백업으로 되돌리고, 끝나면 파일별로 `cmp` 해 **바이트 일치**를 확인한다 — 눈으로 보고 넘어가지 않는다
3. **둘 다 못 하면 A-mut 을 하지 않는다** — A-read 까지만 하고
   `A-mut: N/A — 격리 불가` 로 남긴다. **작업물이 검사보다 중요하다** (되돌리기 어려운 작업은 §되돌리기 어려운 작업이 우선)

### 고치는 것은 코덱스가 아니라 클로드다

```
클로드 구현 → 코덱스가 결함과 재현법을 보고 → 클로드가 재현하고 수정 → 테스트 재실행
```

**코덱스가 본 구현을 고치면 검증자와 저자가 다시 섞인다** — 이 모드에 남은 독립 축이
그 자리에서 사라진다. 코덱스의 출력은 **수정 지시가 아니라 수정 입력**이다.

**재현되지 않는 지적은 채택하지 않는다.** finding 마다 `file:line` 근거와 도달 경로를 요구하고,
재현 안 되면 기각 사유를 한 줄 남긴다. `no finding` 은 기대되는 정상 출력이라고 의뢰서에 명시한다 —
안 그러면 반대를 위한 반대가 나온다.

## 되돌리기 어려운 작업

대상: **보안 · 결제 · 운영 데이터 · 마이그레이션 · 데이터 삭제/이동 · 배포 · 공개 API · 외부 발송.**
이 작업이면 아래를 더한다. **클로드 판단으로 끄지 못한다.** `"코덱스 없이"` 는 어디서나 **관문1 코덱스만** 끈다 —
관문2(구현 검토 · 변형 검사 · 해결 확인)의 코덱스는 남는다. 코덱스를 아예 빼고 싶다는 뜻이면 duet 이 아니라 기본 모드이므로, 그렇게 확인하고 진행한다.

1. **A-mut 필수 — 변형할 구현과 자동 단언이 있을 때.** 격리는 코드 트리만이 아니라 **DB · 파일 저장소 · 외부 서비스**까지 확인한다
   (테스트 설정이 운영 자원이나 실제 발송에 닿지 않는가). 변형할 대상이 없는 작업(예: 메일 발송)은
   `A-mut: 해당 없음` 으로 적고 위험에 맞는 확인 — 수신 대상·내용 미리보기, 모의 실행, 되돌릴 경로 — 을 대신 한다.
   **격리가 안 되면 넘어가지 않고 사용자에게 묻는다.** `해당 없음` 과 `격리 실패` 를 섞어 적지 않는다.
2. **해결 확인** — 관문2 에서 채택한 지적 **하나하나가 최종 변경에서 해결됐는지** 같은 코덱스 스레드
   (`codex exec resume`)로 확인받는다. 미해결이면 고치거나 blocker 로 보고한다. 반복 상한 3회
   (마에스트로 fix-loop 상한을 빌린 값) — 넘으면 사용자에게 보고한다.
   근거: 2026-09-04 런에서 관문2 지적을 반쪽만 고쳤고, 그게 이 모드의 유일한 확정 중대 누락이었다.
3. **실행은 매번 사용자 승인** — 배포 · 삭제 · 외부 발송 · 운영 데이터 쓰기. 프로젝트가 정한 절차가 있으면 그게 우선이다.

## 코덱스가 안 돌아올 때

- **로그 정지 ≠ 멈춤.** 수십 분 안 움직여도 긴 추론 구간일 수 있다. 프로세스가 살아 있으면 기다린다.
- **시간 상한을 두고 백그라운드로 돌린다.** 관문 하나가 막히면 관문 둘로 시점을 옮긴다 —
  포기가 아니라 이동이다.
- **둘 다 실패하면 `N/A — 코덱스 확인 실패` 로 남기고, 그 상태를 완료 보고에 명시한다.**
  독립 축이 0인 채로 완료를 선언하지 않는다.

## 완료 전 확인

**검증 축이 하나도 없으면 완료를 선언하지 않는다.** 테스트·린트·빌드가 전부 부재이거나
`N/A` 면 `— 작업 완료 —` 대신:

```
확인 안 됨 — 이 프로젝트에는 자동 검증이 없습니다.
코드는 바꿨지만 제가 맞는지 확인할 방법이 없었습니다.
직접 확인해 주세요:
  1. <무엇을 눌러보면 되는지>
  2. <무엇이 보이면 정상인지>
```

**검증 수단 부재는 완료의 사유가 아니라 미완료의 내용이다.**

**보고 형식**: 내부 용어는 그 보고에서 처음 나올 때 `용어(쉬운 설명)` 로 한 번 푼다.
결과는 **만든 것 / 확인한 방법(숫자로) / 확인 못 한 것 / 사용자가 할 일** 순서.
숫자는 그대로 — "테스트 통과"보다 "테스트 42개 통과". 코덱스 세션은 `codex resume <id>` 로 한 줄 남긴다.

## 기록 — 시험 중이므로 필수

완료 시 `.agentic/duet-runs.md` 에 한 줄 append (없으면 헤더와 함께 생성).
**기존 파일 헤더에 `규칙 마찰` 칸이 없으면** 표를 이어 붙이지 말고 `## v0.4.0 부터` 절을 새로 열어 아래 헤더로 시작한다.
**`추가 서브에이전트` 칸이 없는 표**(v0.4.0 헤더)는 그대로 두고, 이 칸을 쓰려면 `## v0.4.1 부터` 절을 새로 열어 아래 헤더로 시작한다 — 기존 행을 고쳐 칸을 끼우지 않는다.

```markdown
| 날짜 | 태스크 | 관문1 (findings / 바꾼 결정) | architect (findings / 바꾼 결정) | 추가 서브에이전트 (쓴 것 / 값) | 관문2 (findings / 바꾼 결정) | 오탐 | 놓친 것(단순) | 중대 누락(확정) | 규칙 마찰 | 호출·시간 |
|---|---|---|---|---|---|---|---|---|---|---|
```

| 열 | 무엇을 적나 |
|---|---|
| **관문1 / architect / 관문2** | **따로 센다** — 확인된(재현된) actionable finding 수 **와** 그 때문에 실제로 달라진 결정. 못 잡았으면 `0 / 없음` |
| **오탐** | 재현 안 돼 기각한 지적 수. 관문의 비용 쪽 |
| **놓친 것(단순)** | 사용자가 지적했거나 나중에 드러난 **일반 결함** |
| **중대 누락(확정)** | ownership(데이터 주인) · invariant(불변 조건) · failure mode(실패 처리) 관련 누락. **확정 요건: 클로드가 재현했거나 `@architect` 가 확인한 것만.** 주장만으로는 세지 않는다 |
| **추가 서브에이전트** | 착수 때 정한 것(`추가 없음` 도 적는다)과 끝 평가 — `쓴 것 / 결정을 바꿨나·비용만 들었나`. 안 쓴 작업에서 **쓸 걸 그랬다** 싶은 순간이 있었으면 그것도 적는다 (그게 이 칸의 가장 귀한 값이다) |
| **규칙 마찰** | **규칙 이름과 함께** — 이 모드의 규칙 때문에 불필요하다고 본 일을 해야 했거나, 필요한 일을 못 한 순간. 없으면 `0`. 아래 §규칙 목록의 뺄 때 판단이 이 칸을 근거로 한다 |
| **호출·시간** | 코덱스 N회(실패·timeout 별도 표기) + 서브에이전트 N명 + wall-clock |

**정직 조항**: `0` 이 정상이고 기대되는 값이다. 모드를 정당화하려고 없는 성과를 적지 않는다.

## 규칙 목록 — 뺄 때와 되살릴 신호

규칙은 그것을 만든 문제보다 오래 산다 — 마에스트로가 그렇게 족쇄가 됐다. 그래서 **시험 규칙마다 뺄 때를 적어 둔다.**
**기록이 10런 쌓일 때마다** 규칙마다 `유지 / 축소 / 시험 중단` 중 하나를 결정으로 `.agentic/duet-runs.md` 의 `## 검토` 절에 남긴다.
시험 중단에는 되살릴 신호를 붙인다. (10런은 이 pilot 의 원래 규모 8~10런에서 가져온 값이다.)

## 판정 — 이건 동등성 시험이 아니라 pilot 이다

**8~10런으로는 품질 동등성을 판정할 수 없다.** 결함 1건 차이가 10%p 라 통계적으로 너무 거칠다.
이 구간의 목적은 **위험 신호와 사용성**을 찾는 것이지 "마에스트로만큼 좋다"를 증명하는 게 아니다.

**즉시 대응 트리거 (한 번이라도 발생하면)**

| 신호 | 대응 |
|---|---|
| A-mut 이 사용자 작업물을 훼손 | A-mut 을 격리 worktree 전용으로 고정 |
| 코덱스가 본 구현을 직접 고침 | 의뢰서에 수정 금지를 명시적으로 넣는다 |
| 중대 누락이 확정됐는데 대응 규칙이 이미 있다 | 그 규칙이 **적힌 대로 이행됐는지** 먼저 본다 — v0.3.1 의 "architect 의무 복원" 트리거는 2026-09-04 에 발동했지만 그림자로만 이행됐다 |


**pilot 이 끝나면 볼 것** (판정이 아니라 다음 실험의 설계 근거)

- **결정을 바꾼 비율** — 관문이 실제로 무언가를 바꾼 런의 비율. 낮으면 라우팅이 너무 넓다
- **오탐 비용** — 오탐이 많으면 관문이 시간을 먹는다
- **호출·시간 대비 이익**
- **코덱스 실패·timeout 비율** — 이 모드는 코덱스 의존이 크다

> **관문이 아무것도 못 잡은 런이 많다고 곧바로 무용은 아니다** — 원래 구현이 깨끗했을 수 있다.
> 무용의 증거는 *"못 잡았다"* 가 아니라 *"결정을 바꾼 적이 없는데 오탐과 시간은 들었다"* 다.
