# Visual Axis Rubric — Phase 5d

> UI 청크 검증자(@frontend-engineer)가 **채점표로 쓰는 파일**. 산문 지시가 아니라 항목별 판정이 나와야 한다.
> 축 정의: **"제대로 보이는가"** ≠ "토큰을 올바르게 썼는가". 후자는 코드 리뷰어 축이고, 그 PASS 는 이 축의 PASS 를 의미하지 않는다.

## 수행 조건

실제 렌더가 **필수**다. 스크린샷 없이 코드만 읽고 채점하면 이 축은 미수행이다.

- 뷰포트: **375px (모바일)** + 데스크톱 2종 필수
- 대조 대상 (프로젝트가 공급): DESIGN_SYSTEM / 기능 와이어프레임 / 시각적으로 인접한 기존 페이지
- 대상 트리거: `app/views/**` · Stimulus 등 클라이언트 컨트롤러 · CSS/디자인 토큰 변경. 백엔드·모델·test-only 변경은 비대상. dormant 머지라도 UI 청크면 적용.

### 무엇으로 렌더하나

이 워크플로는 렌더 도구를 지정하지 않는다 — 환경마다 다르다. **있는 것 중 위에서부터 고른다.**

1. **프로젝트가 지정한 것** — `.claude/maestro-axes.md` 등록분 · 프로젝트 e2e/스크린샷 스크립트
2. **세션에 붙어 있는 브라우저 자동화 도구** — 사용자 브라우저를 쓰는 에이전트/확장이 있으면 그쪽. 로그인 상태가 필요한 화면을 잴 수 있는 유일한 수단인 경우가 많다
3. **헤드리스 브라우저** (Playwright · Puppeteer 등) — 로그인 없이 닿는 화면이면 이걸로 충분하고, 회귀를 고정할 때는 오히려 이쪽이 낫다

**상태를 먼저 확인하고 잰다.** V5(상태 렌더)·V8(회귀)은 로그인·데이터 유무에 따라 화면이 달라진다. **반대 상태를 재고 PASS 를 주는 것이 이 축의 대표적 오판이다** — 재기 전에 지금 어느 상태인지부터 확인한다.

**수단이 없으면 PASS 가 아니라 `N/A — 렌더 수단 없음` 이다.** 코드만 읽고 채점하면 미수행이라는 위 조건이 여기서도 그대로다. 오케스트레이터는 이걸 검증 축 하나가 빈 것으로 취급하고 사용자에게 보고한다.

## 채점 항목

각 항목 `PASS` / `FAIL` / `N/A — <사유>`. FAIL 은 **스크린샷 근거 + 무엇이 어긋났는지** 를 함께 적는다.

| # | 항목 | PASS 기준 |
|---|---|---|
| V1 | 모바일 레이아웃 붕괴 없음 | 375px 에서 가로 스크롤 없음, 수평 카드/테이블이 1열로 접힘, 텍스트 잘림 없음 |
| V2 | 데스크톱 레이아웃 | 의도한 그리드/정렬 유지, 과도한 여백이나 늘어난 라인 길이 없음 |
| V3 | 디자인 레퍼런스 일치 | 간격·타이포 스케일·색이 레퍼런스와 같은 시스템으로 읽힘 (픽셀 동일이 아니라 **같은 계열** 판정) |
| V4 | 인접 페이지와의 일관성 | 같은 역할의 기존 컴포넌트와 톤·밀도가 어긋나지 않음 |
| V5 | 상태 렌더 | hover / focus / disabled / 빈 목록 / 긴 텍스트 / 에러 상태가 깨지지 않음 |
| V6 | 포커스 가시성 | 키보드 포커스 링이 실제로 보임 (outline: none 방치 없음) |
| V7 | 대비 | 본문·보조 텍스트가 배경 대비 읽힘 (의심되면 실측) |
| V8 | 회귀 없음 | 변경 페이지 외 공유 파셜을 건드렸다면, 그 파셜을 쓰는 다른 페이지 최소 1개 재확인 |

## 출력 계약

```
visual axis: <PASS | FAIL>
viewports:   375px / <desktop width>  — 스크린샷 <n>장
reference:   <대조에 쓴 레퍼런스>
V1..V8:      <각 항목 판정 한 줄>
findings:    <FAIL 항목별 — 무엇이 / 어디서 / 근거 스크린샷>
```

미수행 항목이 있으면 **PASS 로 보고하지 않는다** — `N/A — <사유>` 로 남기고 orchestrator 가 판단하게 한다.
