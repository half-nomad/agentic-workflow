# Duet Mode

$ARGUMENTS

---

**연주자는 둘뿐이다 — 클로드와 코덱스.**

이 모드는 한 문장으로 정의된다: **네이티브 plan mode 에 코덱스 관문 두 개를 붙인 것.**
그 사이는 전부 클로드 자율이다. 훅 없음, 상태 파일 없음, 절차표 없음.

> **마에스트로와의 관계**: 이 모드는 마에스트로를 대체하지 않는다. 마에스트로의 값 중
> *다른 벤더의 눈* 하나만 남기고 나머지를 네이티브로 되돌린 것이다. 되돌리기 어려운
> 작업은 여전히 `/maestro` 가 맞다 (아래 §라우팅).

## 발동 — 자동으로 켜지지 않는다

**이 모드는 사용자가 `/duet` 을 칠 때만 실행된다.** 아래 기준에 맞아 보여도 **스스로 켜지 않는다.**

맞아 보이면 **한 줄로 제안하고 사용자가 정한다:**

> *"이건 설계 갈래가 둘이라 `/duet` 이 맞아 보입니다 — 켤까요?"*

**왜 제안까지만 하나**: 지금 필요한 건 *"관문이 값을 하는가"* 인데, **스스로 켜면 무엇을 안 켰어야 했는지가
기록에 안 남는다.** 수락·거절 기록이 곧 나중에 자동 발동으로 넘어갈 근거가 된다.

**안 켜기로 판단했을 때도 한 줄 남긴다** — *"이건 답이 하나로 정해져 있어 그냥 하겠습니다"* 정도면 된다.
켠 것만 기록에 남으면 **안 켜서 놓친 경우가 통째로 안 보인다.**

## 라우팅 — 이 모드가 맞는 작업인가

**파일 수로 나누지 않는다.** 20개 파일의 기계적 rename 은 저위험이고, 한 파일의 인증·권한 변경은
고위험이다. 세는 것으로는 위험이 안 잡힌다 — v5.0 이 *"파일 3개면 무조건 complex"* 판정표를
오분류 유도라는 이유로 이미 삭제했는데, 그 실수를 다시 하지 않는다.

**`/duet` 기준 — 하나라도 해당하면:**

- **불확실한 설계 판단이 있다** — 갈래가 둘 이상이고 어느 쪽이 맞는지 코드만 봐서는 안 갈린다
- **모듈 경계 · 상태 · 공개 계약에 영향** — 남이 의존하는 모양이 바뀐다
- **독립 검토가 실제로 유용하다** — 내가 놓칠 만한 각도가 있다
- **되돌릴 수 있으나 실패 시 재작업 비용이 크다**

**`/maestro` 로 남는 것 — 되돌리기 어려운 것:** 보안 · 결제 · 운영 데이터 · 마이그레이션 ·
데이터 삭제/이동 · 배포 · 공개 API · 외부 발송.

**그 외 — 기본 모드.** 답이 하나로 정해져 있고 실패해도 되돌리면 그만인 작업.

**작업 중 되돌리기 어려운 성격이 드러나면 그 자리에서 `/maestro` 로 올린다.** 사용자에게 한 줄로
알리고 올린다 — 판단을 숨기지 않는다.

## 관문 하나 — 설계 (코덱스 1회)

계획 초안을 쓴 뒤, **승인 요청 전에** 코덱스에 넘긴다. 순서가 중요하다: 검토를 반영한
계획으로 승인을 받아야 승인이 통제가 된다.

```bash
CX=$(ls -d ~/.claude/plugins/cache/openai-codex/codex/*/scripts/codex-companion.mjs | tail -1)
REQ=$(mktemp)                      # 고정 경로 금지 — 동시에 뜬 세션끼리 충돌한다
cat > "$REQ" <<'P'
...아래 골격...
P
node "$CX" task --background --prompt-file "$REQ"        # → job ID 즉시 반환
node "$CX" status <job-id> --wait                        # 백그라운드 Bash 로 실행
node "$CX" result <job-id>
```

**프롬프트는 `--prompt-file` 또는 stdin 으로만 준다** — 단일 인자 `task "..."` 는 인용부호·개행이 소실된다.
**companion 을 직접 부른다** — 서브에이전트 경유는 실패가 침묵돼 복구 규정이 발동하지 못한다.

프롬프트 골격 — **네 절 전부 넣는다**:

1. **배경** — 무엇이 기존 구조이고 무엇이 이번 변경인가. 링크로 대신하지 않는다.
   코덱스는 프로젝트 컨텍스트가 0이라, 이 절을 빼면 **원래 그랬던 것을 이번 결함으로 읽는다.**
2. **계획 전문** — 요약이 아니라 그대로.
3. **요구 하나 — 반증**: 이 계획의 사실 주장 중 코드와 어긋나는 것. 파일·줄 번호로.
4. **요구 둘 — 대안**: *"이 계획이 틀렸다면 무엇을 대신 하겠나."* 반박만 받으면 검토이고,
   대안까지 받아야 **설계 참여**다. 이 한 줄이 이 관문의 존재 이유다.

**받은 뒤**: 지적을 코드로 확인한다. 사실인 것만 반영하고, 기각한 것은 기각 사유를 계획에
한 줄 남긴다. **오케스트레이터가 채택 여부를 판단한다 — 코덱스가 계획을 정하지 않는다.**

**끄는 경우는 둘뿐**: 사용자 modifier(`"코덱스 없이"`) · 확립된 패턴의 단순 확장(레포 안에
원본이 있는 복제 수준). 껐으면 **관문 둘을 필수로 만든다.**

## 네이티브 구간 — 전부 자율

**클로드가 직접 짠다.** 위임 금지 훅이 없고, 서브에이전트 호출 의무도 없다.
컨텍스트가 감당 안 될 만큼 큰 작업이면 **스스로 판단해서** 위임한다 — 허용이지 강제가 아니다.

테스트·린트·빌드는 클로드가 직접 돌린다. 검사 커맨드는 프로젝트에서 찾는다
(`package.json` scripts · `Makefile` · CI 설정 · README · `CLAUDE.md`).

**계획서의 사실 주장은 확인한 것만 적는다** — 파일 수 · 건수 · 컬럼·메서드 이름 · 영향 범위는
코드로 확인하고 쓴다. 확인 안 했으면 `추정` 이라고 표시한다. 확인 방법이 곧 검증 기대치가
되므로, 틀린 사실은 멀쩡한 코드를 결함으로 오판할 기대치를 심는다.

## 관문 둘 — 적대 검토 (코덱스 1회)

**두 가지 다른 일이다. 섞지 않는다.**

| 축 | 무엇 | 안전성 |
|---|---|---|
| **A-read — 적대적 구현 리뷰** | 결함·회귀 경로를 찾는 **읽기 검토**. 파일을 안 건드린다 | 항상 안전 — **기본값** |
| **A-mut — 변형 검사(mutation)** | 구현을 일부러 틀리게 바꿔 **테스트가 실제로 죽는지** 확인 | **격리 가능할 때만** |

**A-mut 이 필요한 이유**: 통과하지만 아무것도 지키지 않는 단언은 읽어서는 안 보인다
(실측: 큐 경계 계약에서 61개 테스트가 전부 통과했는데 아무것도 안 지키고 있었다).
**죽지 않는 자리가 이 축의 산출이다.**

**A-mut 은 사용자 작업 트리를 훼손하지 않는다.** 격리 수단을 이 순서로 고른다:

1. **격리 worktree** — `git worktree add` 로 별도 트리에서 변형하고 통째로 폐기한다. **1순위**
2. **원 트리 + 복원 스냅샷** — **worktree 가 실제로 막혔을 때만.** 훅이 자격증명 파일 복사를
   거부하는 환경이 실재한다(2026-08-17 런). 이 경로를 없애면 그런 환경에서 A-mut 이 영구히
   불가능해지고, A-mut 은 *"61개 테스트가 통과하는데 아무것도 안 지키던 것"* 을 잡은 축이다.
   **다만 전제 셋을 먼저 만족해야 한다:**
   - worktree 가 **왜** 막혔는지 한 줄로 확인했다 (추측으로 이 경로에 오지 않는다)
   - 실행 **전에** `git diff > <스냅샷>` 을 떠서 복원 가능함을 확인했다
   - 끝나면 `cmp` 로 **바이트 일치**를 확인한다 — 눈으로 보고 넘어가지 않는다
3. **셋 중 하나라도 못 하면 A-mut 을 하지 않는다** — A-read 까지만 하고
   `A-mut: N/A — 격리 불가` 로 남긴다. **작업물이 검사보다 중요하다**

### 고치는 것은 코덱스가 아니라 클로드다

```
클로드 구현 → 코덱스가 결함과 재현법을 보고 → 클로드가 재현하고 수정 → 테스트 재실행
```

**코덱스가 본 구현을 고치면 검증자와 저자가 다시 섞인다** — 이 모드에 남은 유일한 독립 축이
그 자리에서 사라진다. 코덱스의 출력은 **수정 지시가 아니라 수정 입력**이다.

**재현되지 않는 지적은 채택하지 않는다.** finding 마다 `file:line` 근거와 도달 경로를 요구하고,
재현 안 되면 기각 사유를 한 줄 남긴다. `no finding` 은 기대되는 정상 출력이라고 의뢰서에 명시한다 —
안 그러면 반대를 위한 반대가 나온다.

## 코덱스가 안 돌아올 때

- **로그 정지 ≠ 좀비.** 수십 분 안 움직여도 긴 추론 구간일 수 있다. 취소 전에 `result` 를 먼저 시도한다.
- **시간 상한을 두고 백그라운드로 돌린다.** 관문 하나가 막히면 관문 둘로 시점을 옮긴다 —
  포기가 아니라 이동이다.
- **둘 다 실패하면 `N/A — 코덱스 확인 실패` 로 남기고, 그 상태를 완료 보고에 명시한다.**
  독립 축이 0인 채로 완료를 선언하지 않는다.

## 그림자 검토 — 첫 3~5런 한정

**`@architect` 를 뺀 것은 실험인데, 실험에는 관찰자가 필요하다.** 코덱스와 클로드가 **둘 다** 놓친
설계 누락은 정의상 자기 관찰이 안 된다 — 관찰자가 없으면 복구 트리거는 *사용자 피해나 장애가 나야*
작동한다. 그건 측정 장치 없이 측정하겠다는 말이다.

```
클로드 설계·구현 → 코덱스 독립 검토 → 클로드 재현·수정 → 테스트 완료
                                                          ↓
                                            @architect 그림자 검토
                                        └─ 중대 누락 발견 시 다음 런부터 복구
```

**규칙**

- **결과에 개입하지 않는다** — 그림자 검토는 완료를 막지 않고 fix-loop 를 열지 않는다.
  개입하면 그건 그림자가 아니라 `@architect` 가 그냥 돌아온 것이다
- **예외 하나**: 사용자에게 실제 피해가 갈 결함이면 즉시 보고한다. **측정이 안전보다 앞서지 않는다**
- **하인드사이트를 표시한다** — 그림자는 완성물을 보므로 계획 단계의 `@architect` 보다 유리하다.
  발견마다 **"이걸 설계 단계에서 잡을 수 있었나"** 를 같이 적는다. 아니면 그건 `@architect` 복원의
  근거가 못 된다 (완성물을 봐야만 보이는 것을 계획 단계 검토가 잡았을 리 없다)
- **비용 계측에서 제외한다** — 그림자를 붙인 런은 호출 수가 부풀려져 있다.
  마에스트로 대비 비용 비교는 **6번째 런부터** 쓴다

## 완료 전 확인

**검증 축이 하나도 없으면 완료를 선언하지 않는다.** 테스트·린트·빌드가 전부 부재이거나
`N/A` 면 `— 작업 완료 —` 대신:

```
확인 안 됨 — 이 프로젝트에는 자동 검증이 없습니다.
코드는 바꿨지만 제가 맞는지 확인할 방법이 없었습니다.
직접 확인해 주세요:
  1. <무엇을 눌러보면 되는지>
  2. <무엇이 보이면 정상인지>
```

**검증 수단 부재는 완료의 사유가 아니라 미완료의 내용이다.**

**보고 형식**: 내부 용어는 그 보고에서 처음 나올 때 `용어(쉬운 설명)` 로 한 번 푼다.
결과는 **만든 것 / 확인한 방법(숫자로) / 확인 못 한 것 / 사용자가 할 일** 순서.
숫자는 그대로 — "테스트 통과"보다 "테스트 42개 통과".

## 기록 — 시험 중이므로 필수

완료 시 `.agentic/duet-runs.md` 에 한 줄 append (없으면 헤더와 함께 생성):

```markdown
| 날짜 | 태스크 | 관문1 (findings / 바꾼 결정) | 관문2 (findings / 바꾼 결정) | 오탐 | 놓친 것(단순) | 중대 누락(확정) | 그림자 architect | 호출·시간 |
|---|---|---|---|---|---|---|---|---|
```

| 열 | 무엇을 적나 |
|---|---|
| **관문1 / 관문2** | **관문별로 따로 센다** — 확인된(재현된) actionable finding 수 **와** 그 관문 때문에 실제로 달라진 결정. 못 잡았으면 `0 / 없음`. **세 번째 모드를 안 만드는 것과 관문을 따로 재는 것은 양립한다** — 사용자에게 보이는 명령은 하나여도 계측은 단계별로 한다 |
| **오탐** | 재현 안 돼 기각한 지적 수. 관문의 비용 쪽 |
| **놓친 것(단순)** | 사용자가 지적했거나 나중에 드러난 **일반 결함** |
| **중대 누락(확정)** | ownership(데이터 주인) · invariant(불변 조건) · failure mode(실패 처리) 관련 누락. **확정 요건: 클로드가 재현했거나 `@architect` 가 확인한 것만.** 코덱스나 그림자의 *주장만으로는 세지 않는다* — 이 칸이 `@architect` 복원 트리거를 당기므로, 오탐 하나가 실험을 끝내버린다 |
| **그림자 architect** | 첫 3~5런만. 발견 내용 + **"설계 단계에서 잡을 수 있었나"** |
| **호출·시간** | 코덱스 N회(실패·timeout 별도 표기) + 서브에이전트 N명 + wall-clock. **그림자를 붙인 런은 비용 비교에서 제외** |

**정직 조항**: `0` 이 정상이고 기대되는 값이다. 모드를 정당화하려고 없는 성과를 적지 않는다.

## 판정 — 이건 동등성 시험이 아니라 pilot 이다

**8~10런으로는 품질 동등성을 판정할 수 없다.** 결함 1건 차이가 10%p 라 통계적으로 너무 거칠다.
이 구간의 목적은 **위험 신호와 사용성**을 찾는 것이지 "마에스트로만큼 좋다"를 증명하는 게 아니다.

**즉시 중단·복구 트리거 (한 번이라도 발생하면)**

| 신호 | 대응 |
|---|---|
| **중대 설계 누락 1건 (확정된 것)** — ownership · invariant · failure mode | **`@architect` 의무 호출 즉시 복원.** 비율을 기다리지 않는다. 단 *확정* = 클로드 재현 또는 `@architect` 확인 — 주장만으로는 안 센다 |
| A-mut 이 사용자 작업물을 훼손 | A-mut 을 격리 worktree 전용으로 고정 |
| 코덱스가 본 구현을 직접 고침 | 의뢰서에 수정 금지를 명시적으로 넣는다 |
| 되돌리기 어려운 작업이 duet 으로 들어옴 | 라우팅 기준을 조인다 |

**pilot 이 끝나면 볼 것** (판정이 아니라 다음 실험의 설계 근거)

- **결정을 바꾼 비율** — 관문이 실제로 무언가를 바꾼 런의 비율. 낮으면 라우팅이 너무 넓다
- **오탐 비용** — 오탐이 많으면 관문이 시간을 먹는다
- **호출·시간 대비 이익** — 마에스트로 대비 얼마나 쌌나
- **코덱스 실패·timeout 비율** — 이 모드는 코덱스 의존이 마에스트로보다 크다

> **관문이 아무것도 못 잡은 런이 많다고 곧바로 무용은 아니다** — 원래 구현이 깨끗했을 수 있다.
> 무용의 증거는 *"못 잡았다"* 가 아니라 *"결정을 바꾼 적이 없는데 오탐과 시간은 들었다"* 다.

**@architect 를 뺀 것은 결론이 아니라 실험이다.** 같은 벤더라도 전문 역할 지침 · 깨끗한 별도 컨텍스트 ·
설계 전제 재구성 · 구현 주체의 앵커링 완화라는 값이 남아 있다. 다른 벤더라는 이유만으로 항상 열등한 게 아니다.
